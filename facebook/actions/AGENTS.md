# Інструкції для Facebook actions

- Селектори за текстовими атрибутами Facebook, зокрема `aria-label`, одразу робити нечутливими до регістру через CSS-прапорець `i`: `[aria-label="Upload photo" i]`.
- Порівняння видимого тексту елементів у JavaScript також виконувати без урахування регістру після нормалізації пробілів і приведення обох значень до одного регістру.
- Не створювати окремі гілки лише для варіантів написання на кшталт `Upload Photo` та `Upload photo`, якщо їх покриває один нечутливий до регістру пошук.
- Після зміни селекторів або текстового пошуку додавати чи оновлювати mock-тест, який перевіряє варіант з іншим регістром.
- Для кліків використовувати human-like pointer: прокрутити елемент у viewport, перемістити курсор кількома кроками, зробити паузу перед кліком і коротке утримання кнопки миші.
- Перед кліком дотримуватися шаблону `wait visible → React-стабілізація → повторний пошук свіжого element handle → human click`, бо React може замінити DOM-вузол після першої появи.
- Після дій, які змінюють діалог, меню, preview, privacy або стан кнопки, не читати результат одразу: чекати очікуваного DOM-стану через `waitForFunction` і додавати стабілізаційну паузу.
- У browser actions враховувати повільні проксі: приймати достатній зовнішній `timeout`, використовувати його для DOM-очікувань і не замінювати очікування короткими фіксованими таймерами.
- Після завантаження файлів чекати готовності preview або активного submit, стабілізувати React і повторно підтверджувати готовність безпосередньо перед submit.
