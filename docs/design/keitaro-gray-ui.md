# Keitaro Gray UI

## Призначення

`Keitaro Gray UI` — канонічна назва плоского темно-сірого дизайну AdsBot. Його еталоном є інтерфейс вкладки «Шаблони потоків» і модальні вікна вибору лендінгів та оферів.

Цей стиль потрібно використовувати, коли користувач пише:

- «сірий дизайн»;
- «дизайн як у шаблонах потоків»;
- «як на скрині Keitaro»;
- «зроби в стилі Keitaro Gray»;
- `Keitaro Gray UI`.

Стиль не застосовується автоматично до всього GUI. Нові екрани або наявні вкладки переводяться на нього лише в межах конкретного завдання користувача.

## Джерела істини

У разі розбіжностей використовувати джерела в такому порядку:

1. Компоненти `frontend/src/components/gray-ui/` — поведінка й розмітка.
2. Токени `frontend/src/styles/keitaro-gray.css` — кольори, відступи, межі та стани.
3. Showcase `frontend/src/design/KeitaroGrayShowcase.jsx` — візуальна композиція.
4. Цей документ — правила й пояснення.

Живий еталон відкривається за адресою:

```text
http://127.0.0.1:5173/?gray-ui=1
```

Запуск із папки `frontend`:

```text
npm run design:gray
```

Showcase не завантажує основний `App` і не звертається до робочих API або локальних даних.

## Характер стилю

- Плоскі темно-сірі поверхні без градієнтів.
- Чітка ієрархія через відтінки сірого, межі й відступи.
- Компактні контролі без надмірно великих радіусів.
- Білий текст для важливого, сірий — для пояснень і технічних ID.
- Синій, зелений і червоний використовуються функціонально, а не декоративно.
- Мінімум тіней: вони потрібні лише меню та модальним вікнам.
- В інтерфейсі переважають прямокутні робочі панелі, а не «скляні» картки.

## Заборонені прийоми

У `Keitaro Gray UI` не використовувати:

- фіолетові або синьо-фіолетові градієнти;
- прозорі скляні панелі з `backdrop-filter`;
- неонове світіння;
- радіуси 14–20 px для звичайних полів і кнопок;
- декоративні тіні на кожній картці;
- різнокольорові акценти без значення;
- глобальні змінні старої теми `--accent`, `--panel` і `--stroke` у нових Gray UI компонентах.

## Типографіка

Основний стек:

```css
font-family: "Segoe UI Variable", "Segoe UI", sans-serif;
```

| Елемент | Розмір | Товщина |
|---|---:|---:|
| Заголовок сторінки | 29 px | 700 |
| Заголовок модального вікна або панелі | 20 px | 700 |
| Заголовок секції | 15–17 px | 650–700 |
| Назва картки або елемента | 14 px | 650–700 |
| Основний текст і контрол | 14 px | 400–600 |
| Допоміжний текст | 12–13 px | 400 |
| Технічний ID | 12 px | 400 |

Правила:

- Заголовки короткі та без крапки в кінці.
- Технічний ID не повинен конкурувати з назвою.
- Для довгих назв використовувати `text-overflow: ellipsis`.
- Не використовувати верхній регістр для великих абзаців.

## Геометрія та відступи

- Поле, кнопка, пошук або select: висота `38–40 px`.
- Радіус поля або кнопки: `6 px`.
- Радіус картки: `7–8 px`.
- Радіус модального вікна: `12 px`.
- Внутрішній відступ картки: `10–16 px`.
- Відстань між близькими контролами: `8–10 px`.
- Відстань між секціями: `22–26 px`.
- Межа: `1 px solid var(--kg-border)`.

Великі порожні відступи допускаються у робочій області, але елементи однієї форми мають залишатися компактними.

## Кнопки

### Основна

- Лише одна головна дія в межах панелі або модального вікна.
- Синій фон `--kg-primary`.
- Приклади: «Зберегти», «Створити», «Застосувати».

### Другорядна

- Сірий фон і сіра межа.
- Приклади: «Додати офери», «Додати лендінги», «Скасувати».

### Небезпечна

- Червоний використовується тільки для видалення або незворотної дії.
- Іконкова кнопка повинна мати зрозумілий `aria-label`.

### Неактивна

- Приглушені межа, фон і текст.
- Курсор `not-allowed`.
- Неактивність не позначати лише зменшенням прозорості тексту.

## Поля й пошук

- Поле має постійно видиму межу.
- Label розташовується над полем на відстані `8 px`.
- Placeholder коротший за label і не замінює його.
- Фокус позначається синьою межею `--kg-focus`.
- Іконка пошуку знаходиться ліворуч усередині поля.
- Пошук фільтрує список одразу після введення.

## Випадаючі меню

- Фон меню: `--kg-control`.
- Меню має межу, невелику тінь і радіус `7 px`.
- Висота списку обмежується, після чого з’являється вертикальна прокрутка.
- Активний пункт і наведення мають сірий фон `#303030`.
- Пошук розташовується першим елементом меню, якщо варіантів багато.
- Меню повинно перекривати картки та списки під ним.

Важливе правило шарів: батьківський контейнер select не повинен обрізати меню через `overflow: hidden` або `overflow: auto`. Прокручуваним робиться список даних, а не вся панель із toolbar. Саме це правило запобігає напівперекритим меню у виборі лендінгів та оферів.

## Картки лендінгів та оферів

Порядок інформації:

1. Назва — біла й напівжирна.
2. ID та група — сірі й менші.
3. Частка у відсотках.
4. Перемикач стану.
5. Видалення.

Картка має бути клікабельною лише тоді, коли клік по всій площі справді виконує одну дію. Інакше використовувати окрему кнопку.

## Перемикач стану

- «Увімк.» — зелений лише в активному стані.
- «Вимк.» — червоний лише в активному стані.
- Неактивна половина перемикача залишається сірою.
- Стан має бути зрозумілим із тексту, а не тільки з кольору.

## Модальні вікна

- Затемнення фону: `rgba(8, 9, 12, .82)`.
- Ширина залежить від задачі, але не перевищує доступне вікно.
- Заголовок і пояснення розташовані ліворуч, закриття — праворуч.
- Toolbar пошуку й групи розташовується над прокручуваним списком.
- На вузькому екрані колонки toolbar переходять в один стовпець.
- Закриття має працювати кнопкою з `aria-label="Закрити"`.

## Порожні, помилкові та завантажувальні стани

- Порожній стан: сіра пунктирна межа й короткий текст.
- Завантаження: індикатор і конкретний текст, що саме завантажується.
- Помилка: короткий заголовок, пояснення та доступна наступна дія.
- Не використовувати червону заливку великих площ без критичної потреби.

## Адаптивність

На ширині до `720 px`:

- дві колонки полів переходять в одну;
- toolbar модального вікна переходить в одну колонку;
- частка і перемикач картки переходять під назву;
- горизонтальна прокрутка форми не допускається;
- меню select залишається в межах viewport.

## Готові компоненти

Імпорт:

```jsx
import {
    GrayAssetRow,
    GrayButton,
    GrayCard,
    GrayField,
    GrayInput,
    GrayModal,
    GraySearch,
    GraySelect,
} from "../components/gray-ui/index.js";
```

Новий екран спочатку потрібно складати з готових компонентів. Новий Gray UI компонент створюється лише тоді, коли наявні компоненти не покривають потрібну поведінку.

## Контрольний список для агента

Перед завершенням GUI-зміни перевірити:

- використані `--kg-*` токени;
- немає фіолетового градієнта або скляного ефекту;
- кнопки мають правильну функціональну роль;
- label не замінений placeholder;
- dropdown не обрізається контейнером;
- список має власну прокрутку;
- довгі назви не руйнують layout;
- є hover, focus, disabled та empty стани;
- іконкові кнопки мають `aria-label`;
- вузьке вікно не створює горизонтальну прокрутку.
