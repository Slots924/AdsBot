# Відновлення locked Facebook-акаунта

`ensureFacebookAccountActive(adsPower, profile, page, options)` запускає recovery лише для `ACCOUNT_LOCK`. Усі дії виконуються через видимий DOM та Puppeteer keyboard/mouse, без відтворення внутрішніх Facebook API-запитів.

Workflow: `facebook/workflows/recoverLockedAccount.js`. Результат містить `recovered`, `passwordChanged`, `credentialsSaved`, `step`, `code`. Новий пароль вважається підтвердженим після переходу з Save changes до авторизованого інтерфейсу або відомого protection dialog. Після цього він одразу зберігається в AdsPower. Повторюється лише збереження, максимум тричі.

Пароль береться з `options.newPassword`, потім `FACEBOOK_RECOVERY_NEW_PASSWORD`, потім локального `data/local-secrets/facebook-recovery.json` із полем `newPassword`. Локальний файл виключений із Git. Якщо налаштування відсутні, з'являється захищене поле введення в браузері. Секрети не додавайте до коду чи документації.

Платформи читаються сервісом `services/adspower/profileCredentials.js`. Домен нормалізується; пошук Firstmail виконується за доменом платформи `firstmail.ltd`, а не за доменом адреси email. Відсутня платформа повертає `null`; неоднозначний або неповний запис викликає помилку. Оновлення зберігає інші платформи та 2FA. Для основної платформи також синхронізуються верхні поля профілю. Нотатка `Новий пароль Facebook: …` додається без обрізання попередніх нотаток та без дублювання того самого рядка. Після запису дані перечитуються для перевірки.

Наявність декількох email у recovery вимагає ручного уточнення: workflow завершується з `AMBIGUOUS_EMAIL_CONTACT`, не вибираючи випадкову адресу. Підтримуються англійські екрани, надані у прикладі. Невідомий екран очікується до таймауту, не клікається навмання.

## Ручний запуск

З кореня проєкту:

```powershell
npm install
node scripts/manual/testFacebookLoginStatus.js 2244
```

Профіль за замовчуванням — 2244. Другий аргумент задає тривалість спостереження після workflow в мілісекундах (типово 90000). Код автоматично отримується з Firstmail через IMAP. Очікування — 60 секунд від початку відстеження безпосередньо перед відправленням коду. Enter у терміналі завершує заключне спостереження, Ctrl+C скасовує recovery. Профіль залишається відкритим.

Консоль показує короткі українські повідомлення: дію, результат, перехід, залишок часу пошти та причини відсіву листів/невдач. JSONL у `data/logs/manual-recovery/` зберігає ті самі події структуровано. Повторюваних DOM-знімків і подій руху миші немає. Незмінний екран не журналюється кожні 3 секунди; поштовий прогрес показується кожні 10 секунд і при нових листах. Журнал не містить значень input, повного DOM, довільного тексту сторінки, кодів, паролів, 2FA, тіл мережевих запитів, cookie або query-параметрів URL.

## Firstmail та отримання коду

`classes/Firstmail.js` використовує ImapFlow і MailParser. Типове з'єднання — `imap.firstmail.ltd:993` через TLS; hostname можна змінити через `FIRSTMAIL_IMAP_HOST`. Пошта відкривається лише для читання. Перед recovery-кліками перевіряються облікові дані та авторизація. Відсутній або неповний запис дає `FIRSTMAIL_CREDENTIALS_NOT_FOUND`, помилка авторизації — `FIRSTMAIL_AUTH_FAILED`, недоступне з'єднання — `FIRSTMAIL_CONNECTION_FAILED`.

Перед Next, який надсилає код, сервіс `services/mail/prepareFacebookCodeWaiter.js` фіксує UIDVALIDITY/UIDNEXT, підписується на нові листи та додатково перевіряє їх кожні 2 секунди. Межа UID відсікає попередні листи незалежно від прочитаності. Перевіряються точний відправник `security@facebookmail.com`, отримувач, відома тема і збіг шестизначного коду в темі та тілі. Код, отриманий до появи поля у Facebook, зберігається в пам'яті; його не втрачаємо через повільний DOM. Для однієї пошти допускається лише один активний waiter.

Через 60 секунд без коду повертається `FIRSTMAIL_CODE_TIMEOUT`. Якщо UIDVALIDITY змінився або з'єднання обірвалось, workflow зупиняється з окремою помилкою; автоматичного читання старих листів, повторного надсилання або переходу до ручного коду немає. Якщо запуск почався вже на екрані коду без підготовленої межі UID, повертається `FIRSTMAIL_SEND_REQUIRED`; почніть recovery з початкового екрана. Відхилений Facebook код дає `FACEBOOK_CODE_REJECTED`.

Якщо locked-акаунт не вдалося відновити, `ensureFacebookAccountActive()` додає тег Login Error через наявний сервіс. Ця гілка не додає BAN, навіть якщо після recovery змінився checkpoint URL. Обробка незалежно виявленого BANNED залишається окремою.

Для ізольованих перевірок можна передати `options.requestConfirmationCode(context)` або `options.firstmailClient`. У робочому запуску за замовчуванням використовується Firstmail. Значення коду, облікові дані та вміст листів не журналюються. Журнал містить події підключення, готовності слухача, UID листів, причини відсіву, успіх і таймаути.

Якщо пароль змінився, але `credentialsSaved` дорівнює `false`, повторюйте `saveRecoveredFacebookPassword()` із тим самим паролем; повторно запускати зміну пароля для виправлення збереження не потрібно.

`passwordChangeUnconfirmed: true` у невдалому результаті означає, що спроба Save changes була, але перехід не вдалося підтвердити (наприклад, вкладку закрито або задачу скасовано). Це не доказ успішної зміни; перевірте стан у відкритому браузері.

Ізольована перевірка без зовнішніх API: `node scripts/verifyFacebookRecovery.js`. Вона охоплює регістр тексту, приховані та disabled-дублікати, неправильний код, гілку поточного пароля, відсутність protection dialog, збереження інших платформ/2FA, збій запису та скасування. Наявні тести з папки `test` автоматично не запускаються.

`node scripts/verifyFirstmailCode.js` перевіряє парсер листа, старі UID, буферизацію раннього листа, таймаут, скасування, зміну UIDVALIDITY, блокування поштової скриньки та тегування Login Error. Перевірка не читає реальні листи.
