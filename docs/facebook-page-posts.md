# Пости та обговорення фанпейджі

У вкладці фанпейджі під постом відображаються `reactionCount` і `commentCount`.
`FacebookGraphApi` отримує їх разом із постами через
`reactions.limit(0).summary(true)` і `comments.filter(stream).limit(0).summary(true)`.
Тексти коментарів при цьому не завантажуються. Кількість коментарів включає відповіді.
Якщо лічильник відсутній у відповіді або старому кеші, GUI показує `—`.

Поле `reactionCounts` містить розподіл за `LIKE`, `LOVE`, `CARE`, `HAHA`, `WOW`,
`SAD` і `ANGRY`. Один набір Graph-полів `reactionSummaryFields` отримує ці
лічильники через `reactions.type(TYPE).limit(0).summary(true).as(reactions_type)`
як для постів, так і для коментарів та відповідей у вже наявних запитах.
Компонент `ReactionCounts` показує емодзі та кількість для ненульових реакцій.
За відсутності розподілу у старому кеші показується загальна кількість;
після оновлення постів надходить розподіл. Невідомі значення не замінюються нулями.

Після натискання «Розгорнути» компонент `PagePostDiscussion` викликає
`pages:post-comments` через preload → `AdsBotGuiService` →
`FacebookBackendService` → `FacebookGraphApi.getPagePostComments`.
Метод використовує токен сторінки та наявний HTTP-клієнт із проксі.
Запит `/{postId}/comments` із `filter=stream`, `order=chronological`, `limit=25`
повертає коментарі й відповіді в одній порції. Відповіді позначаються через `parentId`.
Кнопка «Показати більше» передає курсор `after`; URL пагінації й токени в GUI не передаються.

Обговорення зберігається лише в стані компонента. Згортання залишає вже отримані
коментарі до наступного оновлення постів. Оновлення постів, зміна фанпейджі чи
акаунта скидають обговорення та ігнорують запізнілі відповіді. Автоматичного
завантаження коментарів після оновлення немає.

## Оновлення вибраної фанпейджі

`pages:selected-refresh` отримує `getPageSnapshot` через GUI/backend-сервіси.
Метод знаходить токен і локальні дозволи сторінки один раз, після чого паралельно
виконує два Graph-запити: деталі з `is_published` та п'ять останніх постів.
Окремі попередні перевірки `id,name,is_published` для цього оновлення не виконуються.
Якщо список доступних сторінок ще не завантажений, спочатку отримується `/me/accounts`.

Дані повертаються з попередніми локальними зображеннями. Поля `pictureSourceUrl`
та `thumbnailSourceUrl` зберігають джерело картинки, а `picturePending` і
`thumbnailPending` позначають необхідність її оновлення. За незмінного джерела
використовується дисковий кеш без повторного завантаження. Під час першого
оновлення старого кешу без цих полів картинки перевіряються повторним завантаженням.

Нові картинки завантажуються окремо через наявний proxy client після повернення
результату IPC. `patchPageSnapshotImages` змінює лише поля зображень, якщо ID та
джерело досі збігаються з актуальним кешем. Патч не змінює тексти, лічильники чи
склад постів. Подія `page-images` оновлює GUI без згортання відкритих коментарів.
У разі невдалого завантаження залишається попередня картинка, а наступне ручне
оновлення повторює спробу.
