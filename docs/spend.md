# Спенд Meta → Keitaro

## Призначення

Підсистема спенду зберігає локальні денні знімки витрат Meta та передає їх у
Keitaro з фільтром за `sub_id_2`, де очікується Meta campaign ID.

База знаходиться у `data/spend/spend.sqlite`. Це локальний SQLite-файл. Для
запису використовується вбудований модуль Node.js `node:sqlite`; окрема
залежність або сервер бази даних не потрібні.

## Збір із Meta

- Задача `spend-collect` послідовно перевіряє всі API-клієнти.
- Доступні рекламні акаунти об'єднуються за Graph ID, тому дубльований доступ
  через кілька API-клієнтів не створює повторних записів.
- Якщо запит через перший клієнт не вдався, використовується наступний клієнт,
  який бачить той самий рекламний акаунт.
- Insights запитуються на рівні кампанії з `time_increment=1`.
- Перший запуск бере дані від дати початку в налаштуваннях. Наступні запуски
  повторно перевіряють останні п'ять днів або іншу задану кількість.
- Поточний контрольний час округлюється вниз до 15 хвилин.

Збереження грошей виконується цілим числом у мільйонних частках валюти. Це
усуває помилки двійкової арифметики JavaScript.

Чистий спенд Meta зберігається без змін. Перед передачею в Keitaro до нього додається
комісія з налаштувань спенду. Зміна відсотка комісії автоматично ставить раніше
передані періоди в чергу на повторний перерахунок із новою повною сумою.

## Передача в Keitaro

Задача `spend-export-keitaro` будує звіт Keitaro з вимірами `campaign_id` та
`sub_id_2`. З нього створюється відповідність Meta campaign ID до кампанії
Keitaro. Якщо відповідності немає або їх кілька, витрати не передаються, а у
вкладці «Спенд» показується проблема.

Для однозначної відповідності викликається
`Keitaro.updateCampaignCosts(keitaroCampaignId, payload)` з:

```json
{
  "start_date": "2026-09-03 00:00:00",
  "end_date": "2026-09-03 15:00:00",
  "cost": "12.5",
  "currency": "USD",
  "timezone": "Europe/Kyiv",
  "filters": {
    "sub_id_2": "META_CAMPAIGN_ID"
  }
}
```

Успіх доставки фіксується окремо для Meta campaign ID, кампанії Keitaro та
дня. Повторний запуск пропускає незмінені суми й повторює невдалі.

## Автоматизація

Ручні кнопки та розклад використовують ту саму глобальну чергу фонових задач.
Одночасний дубль задачі одного типу не створюється. Якщо програма була закрита
у запланований момент, прострочена задача додається до черги після наступного
запуску програми.

Початкові налаштування:

- дата початку — `2026-09-01`;
- комісія перед передачею в Keitaro — `10%`;
- автоматичний збір вимкнено;
- автоматична передача вимкнена;
- інтервали — 60 хвилин;
- повторна перевірка — 5 днів.
