# Spend Server

У налаштуваннях застосунку відкрийте **Spend Server** та збережіть HTTPS-адресу і `Client Key`, якщо сервер вимагає його. Адреса автоматично доповнюється `/fb_data/add`. Cookies спочатку підставляються з `account-053`, User-Agent — стандартний Windows із наявного списку програми. Ці дані можна змінити в налаштуваннях.

Після успішної ручної або автоматичної перевірки API-клієнта в режимі AFP програма виконує POST. Передаються `schemaVersion: 3`, стабільний `installationId`, поточний `sentAt`, `enabled: true`, `reason: manual`, версія застосунку, AFP-токен клієнта та cookies і User-Agent із налаштувань Spend Server. Cookies мають містити `c_user` і `xs`.

Сервер вимагає UUID, а локальні ID мають формат `account-053`. Тому `installationId` детерміновано утворюється з `AdsBot:<accountKey>` через SHA-256 у форматі UUID. Для одного клієнта результат завжди однаковий; готовий UUID передається без перетворення.

Індикатор біля AFP-клієнта зелений після HTTP 2xx, червоний після помилки, сірий до відправки. Зміна токена або налаштувань відправки скидає статус. Кожна наступна успішна перевірка повторно відправляє дані. Переадресації вимкнені, тайм-аут — 20 секунд. Текст відповіді сервера не потрапляє в повідомлення про помилку.

Налаштування та результати відправок зберігаються у `data/local-secrets/spend-server.json`, який виключений із Git. У результатах зберігається хеш прив’язки до токена й налаштувань, а також час або безпечне повідомлення помилки.

Перевірки: `node --test test/spendServer.test.js`, `node test/testGuiIpcMock.js`, `npm --prefix frontend run test -- src/test/spend-server-settings.test.jsx`, `npm --prefix frontend run build`.
