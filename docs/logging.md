# Logger і звіти AdsBot

Desktop GUI використовує один `AppLogger`. Він записує структуровані JSONL-події
в `data/logs`, передає безпечну копію події у renderer та переносить контекст
фонової задачі через `AsyncLocalStorage`.

## Формат і безпека

Подія містить `id`, `timestamp`, `level`, `scope`, `event`, `message`, `context`
і `fields`, а також `userVisible` для керування показом у нижній панелі подій.
Секретні ключі, access tokens, cookies, authorization, proxy
credentials, UTM і паролі приховуються до запису у файл та до IPC. Stack trace
зберігається тільки у файловому sink.

Файли мають формат `adsbot-YYYY-MM-DD[-part].jsonl`, сегментуються після 10 MB
і зберігаються максимум 30 днів та 100 MB. Logger не повинен зупиняти робочу
операцію через помилку файлової системи. Перед виходом Electron викликає
`flush()`.

Режим `info` є стандартним. `debug` вмикається у налаштуваннях GUI й впливає
лише на нові записи.

## Видимість у журналі подій

Файлове збереження визначається рівнем логування. Позначка `userVisible: false`
впливає лише на передавання через `log:event`: Electron не надсилає такі записи
у нижню панель «Журнал подій». Вони залишаються у JSONL-файлах і доступні через
`logs:list` у вкладці «Журнал».

Для технічних записів використовуйте четвертий аргумент методів логера:

```js
logger.info("api.response", "API відповів", { response }, { userVisible: false });
logger.info("task.finished", "Задачу завершено", { taskId });
```

За замовчуванням `info`, `warn` і `error` видимі, а `debug` прихований від панелі.
Graph API запити та успішні відповіді, включно з відповідями з попередженнями,
приховані. Помилки Facebook показуються коротким повідомленням; діагностичні
поля зберігаються у записі. Повідомлення про задачі та їхні результати видимі.

`installConsoleBridge()` записує `console.*` через логер без дублювання в
термінал. Якщо серед аргументів є об'єкт, масив або `Error`, запис залишається
лише у файловому журналі та вкладці «Журнал». Звичайні текстові повідомлення
видимі у панелі; `console.debug` прихований. Помилка самого файлового журналу
залишається видимою і додатково повідомляється через `stderr`.

## Звіти

`TaskReportManager` зберігає по одному JSON у `data/reports/tasks` для кожного
фінального стану задачі. Видалення задачі з task journal не видаляє звіт.
Markdown формується лише вручну через вкладку «Журнал → Звіти».

Публікація постів є задачею типу `publication` і використовує глобальний ресурс
`facebook-page-publish`, тому всі публікації виконуються послідовно. IPC
`post:publish` одразу повертає `{ taskId, task }`.

## IPC

- `logs:list`, `logs:scopes`, `logs:level-set`, `logs:renderer-write`;
- `reports:list`, `reports:get`, `reports:delete`,
  `reports:export-markdown`;
- події наживо надходять через `log:event`.

Renderer ніколи не читає log/report файли напряму.
