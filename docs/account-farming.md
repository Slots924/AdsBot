# Фарм акаунтів

У «Акаунти під коментарі» виберіть профілі та натисніть «Додати до групи фарму».
Групи фарму локальні й не залежать від груп AdsPower. Акаунт має одну поточну
групу; перенесення зберігає історію. Назва в таблиці редагує назву AdsPower,
а не ім’я Facebook. Чекбокси дозволяють змінювати AdsPower-групу масово.

У вкладці «Фарм акаунтів» доступні акаунти, нотатки з абзацами, порівняння,
історія запусків і спільні налаштування. Зміни налаштувань потрібно зберегти.
Перед запуском виберіть акаунти та потрібні дії. Запусків за розкладом немає.
Зупинка й звіти доступні через стандартну панель фонових задач.

## Виконання

- Воркери 1–5 визначають кількість одночасних акаунтів; початково 1.
- Початковий таймаут — 500 секунд від початку відкриття профілю. Готовність
  AdsPower перевіряється перед цим. Вхід, активність і English входять у таймаут.
- Проксі береться з профілю; фарм не призначає проксі воркерам і не змінює її.
- Вікно 1280×1440, proxy detection увімкнений, попередні вкладки не відновлюються.
  Вимкнення картинок і headless початково вимкнені.
- Обрані блоки дій виконуються у випадковому порядку. Кількості — верхні ліміти
  сесії. Відсоток лайків — незалежна ймовірність для кожного переглянутого поста
  або коментаря, а не гарантія точної частки. Ліміти лайків спільні для сесії.
- Для самостійного лайкання постів кількість кандидатів і паузи беруться з
  налаштувань стрічки. Для лайків коментарів використовується окрема кількість постів.
- Вже встановлені лайки пропускаються. Пости відкриваються в тимчасових вкладках,
  які закриваються після перегляду. Заявки у групи фіксуються як очікування;
  анкети не заповнюються. Пул обирається без повторення груп у межах сесії.
- Після завершення лімітів сесія закінчується раніше таймауту. За дедлайном
  браузер закривається для припинення DOM-операцій, після чого через `AdsPower`
  надсилається stop; очікування кожного етапу очищення обмежене 10 секундами.
  Помилки закриття видно в історії. Наступна сесія повторно перевіряє стан профілю.

## Статистика та зберігання

Таблиці `farm_*` використовують ту саму SQLite-базу, що й `ProfileActivityStore`,
але не мають каскадної залежності від рядків старого журналу. База, WAL і SHM
залишаються локальними у `data/profile-activity/`; вони містять дані профілів.

Лічильники UI/API-оформлення, комент-задач і лайк-задач зберігають наявну
семантику. Окремі кліки та реакції не додаються до цільових лічильників.
Кількість фарм-сесій включає сесії, які дійшли до виконання фарму.
Невдалі перевірки, пропуски й причини завершення показуються окремо.

Сумарний час фарму включає дії та паузи після перевірок, до припинення дій;
очищення браузера не входить. Період фарму — різниця між початком першої й кінцем
останньої фактичної сесії. Відсутні історичні часові дані не відновлюються штучно.
Після аварії враховується лише час до останнього збереженого кроку,
а незавершені сесії позначаються перерваними без автоматичного повторення.

Порівняння груп використовує всю історію їхніх **поточних** акаунтів, навіть
якщо частина дій виконувалася до перенесення. Історія запусків залишається за
групою на момент запуску. Видалення групи є архівацією; запусків воно не видаляє.
Стан Facebook кешований із датою перевірки; для актуального стану натисніть
«Перевірити акаунти». Невідомий стан не означає активність.

## IPC та AdsPower

Preload: `getFarmSnapshot(groupId)`, `saveFarmGroup(group)`, `deleteFarmGroup(id)`,
`assignFarmProfiles(groupId, profileNos)`, `saveFarmSettings(settings)`,
`saveFarmPool(pool)`, `runFarm({ groupId, profileNos, actions })`.
`groupId: null` у призначенні вилучає акаунти з групи.
`runFarm` повертає стандартний `{ taskId, task }`; налаштування фіксуються при
постановці в чергу, членство повторно перевіряється перед виконанням.
Вибрані профілі резервуються ресурсами `adspower-profile:<номер>`.

У класі `AdsPower` метод `request` отримав необов’язковий п’ятий параметр
`{ signal, timeout }`. `openProfile` приймає `options.signal`, `closeProfile` —
необов’язковий `{ signal, timeout }`. Черга й інтервал запитів спільні як раніше;
скасований запит перевіряється перед відправленням і не ламає чергу.

дев’ять мов і перевірені mock-тестами; це не підтвердження їхньої роботи наживо.

## Локальні перевірки

`npm run test:farming`, `npm --prefix frontend run test -- src/test/farming.test.jsx`,
`npm run gui:build`. Живі перевірки запускаються лише на явно вибраному профілі.

Ручний тест: `node scripts/manual/testFarmProfile.js <номер-профілю> [таймаут-секунд]`.
Він запускає лише перегляд стрічки, перевіряє розмір вікна, зупинку за дедлайном,
закриття профілю та незмінність налаштувань проксі. Не змінює членство у групах
фарму, не встановлює реакцій і не вступає до Facebook-груп. Службові логи
приховані, щоб не друкувати дані акаунта чи проксі.
